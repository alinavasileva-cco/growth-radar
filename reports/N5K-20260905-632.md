## Technical diagnosis

The available GitHub contents writer can replace an existing file only by sending the complete replacement UTF-8 content. Both aggregate masters are ~1.1–1.2 MB. The connector's fetch of the current large blobs is truncated at the transport layer; no repository-side append/merge executable exists in `scripts/`, and `.github/workflows` has no existing workflow for canonical append. Creating only a shard/increment would violate the required synchronization contract, so no partial canonical write was performed and no company was counted.

This write blocker is local to physical qualification; it does **not** block fresh discovery. `new_discovery_allowed=true` is restored in runtime.
